(AI总结与生成)，从毛玻璃样式的界面到带歌词的音乐播放器，最后都落地了。这篇把技术栈和功能整理一遍，算是给自己留个记录，也给想搭同类站点的人一个参考。

## 技术栈

核心就四样：**Astro 5** 负责生成静态页面，**Keystatic** 做可视化后台，**GitHub Pages + Actions** 负责托管和自动部署，剩下交给 **Tailwind CSS 4** 和少量 **React** 组件处理样式与交互。

选 Astro 的原因很直接：它是内容站的一等公民，默认几乎不带 JS，构建出来的就是纯 HTML。博客这种以阅读为主的场景，加载速度比什么都重要。React 只用在需要交互的地方，比如音乐播放器、站内搜索、文章标签筛选，不会整站塞一个巨大的前端框架。

Keystatic 是内容管理的核心。它是个 Git-based 后台，保存的内容直接写成 Markdown 和 JSON 文件落在仓库里，不占数据库。写文章、传歌、改站点设置都在本地 `/keystatic` 界面完成，保存即落盘，`git push` 即发布。

代码本身是 TypeScript strict，附了一百多个单元测试，GitHub Actions 每次构建都会先跑类型检查和测试，有问题就发不出去。

## 内容结构

站点内容全部是文件，分门别类放在 `src/content/` 下：

- **文章**：Markdown 加 frontmatter，支持摘要、封面、标签、置顶、草稿
- **说说**：短小的碎片记录，首页有轮播，独立页看全部
- **歌曲**：JSON 记录歌名、歌手、歌单、音频、歌词、评分和乐评
- **友链、照片墙**：各是一个集合，后台直接增删
- **站点设置**：博客名、简介、头像、社交链接、壁纸和特效开关都在一个单例里

写文章时 `draft: true` 的文章不会出现在列表和 RSS 里，适合写一半先存着。

## 音乐系统

音乐是这个博客最有存在感的部分。后台「歌曲」集合里上传音频（支持 mp3 / flac / m4a / ogg / wav），填上歌名、歌手和歌单名就行。mp3 和 flac 内嵌的标题、作者、封面会自动识别回填，不用手敲。

歌词支持两种方式：上传 `.lrc` 文件，或者直接在后台粘贴 LRC 文本。播放时会逐行高亮，歌词区域自己滚动，不抢页面的滚动条。

首页顶部是时钟和播放器的组合，打开网站会自动开始播上次听的歌；被浏览器自动播放策略拦下来时，点一下页面任意位置就续上。右下角有迷你播放器，切页面不停歌。音乐页支持按歌单筛选，每首歌有 1-5 星评分和一段乐评，还能把歌加入播放队列。

播放器记住音量、播放模式和上次的歌曲，刷新也不丢。顺序、随机、单曲循环三种模式一键切换。

后台传大文件容易卡，所以单独做了批量导入：在歌曲列表页点「导入歌曲」按钮，选好音频文件，程序自动读元数据、提封面、写条目，大小不限；照片墙也有对应的批量导入按钮。

## 其他功能

简单列一下：

- **搜索**：按 `/` 或左下角按钮打开，中文前缀加模糊匹配，索引覆盖文章和说说全文
- **文章页**：默认展示全部文章，顶部标签一键筛选；归档页按年份聚合；RSS 和 sitemap 自动生成
- **深色模式**：默认深色，手动切换后记住选择
- **背景特效**：粒子光点、流动光晕、壁纸，全部可以在后台开关，还支持减弱动态效果
- **PWA**：可以安装到桌面，基础离线缓存
- **细节**：代码块带语言标签和复制按钮，正文图片点开有灯箱，文章页有阅读时间和相关文章推荐，滚动有进度条和返回顶部

## 部署流程

代码推到 GitHub 的 `main` 分支，Actions 自动跑一遍检查、压缩图片、构建，然后发布到 GitHub Pages。整个流程几分钟，改完内容只需要 `git push`。

这套组合的取舍很明确：没有服务器、没有数据库、没有运维成本，换来的是内容管理和发布流程稍微有点 Geek。写文章要先在本地起服务，改完记得提交推送。对想长期维护个人博客的人来说，这个交换挺划算。
